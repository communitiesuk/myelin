myelin's first weeknote covers the project so far. Since late August it has
grown from a set of skills into a released plugin, now at version 0.6.2,
that takes a piece of work from a first conversation through a reviewed
decision and plan to a change written test-first, with the git history
recording how each step came from the one before. This week landing a
branch learned to wait for the checks a project requires, and myelin opted
into its own public project site.

## Deciding and planning
- Decisions are recorded as ADRs, reviewed before they are accepted, and
  revised in place, with every downstream plan or skill accounted for.
  (docs/adr/0008-stage-reviews.md, docs/adr/0009-adr-acceptance.md,
  docs/adr/0011-revision-process.md)
- Ideas still being worked out are captured as discovery notes before any
  decision. (docs/adr/0006-where-do-captured-ideas-live.md)
- Deferred work records the condition it waits on, and is picked up when
  that condition is met. (docs/adr/0012-discharging-deferrals.md)

## Building and landing work
- Every piece of work gets its own branch and lands with its history
  intact; the relationships between artefacts live in git, not in the tree.
  (docs/adr/0003-git-workflow.md, docs/adr/0004-where-does-history-live.md)
- Landing a branch now waits for the checks the trunk requires before it
  merges. (#218)
- New skills are written eval-first, and code test-first.
  (docs/adr/0002-skill-forge.md)

## Using myelin
- A history skill answers which decisions are closed and what depends on
  what. (docs/adr/0010-history-retrieval.md)
- A setup check reports what a repository needs before myelin can run, and
  the README says it up front. (docs/adr/0007-readme-requirements-and-opinions.md,
  docs/adr/0013-requirements-declared-and-verified.md)
